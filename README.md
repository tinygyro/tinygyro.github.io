# 每日技术简报 · Tech Daily Brief

基于 GitHub Pages 的中文静态简报站点，关注 AI / 大模型 / OpenAI、网络安全 / IEC 62443 / CRA、嵌入式 / MCU / RTOS、VFD / 工业自动化。

- 网站首页：<https://tinygyro.github.io/>
- 首期简报：<https://tinygyro.github.io/daily/2026-10-08.html>
- 内容结构：核心摘要、为什么值得关注、原始来源、延伸阅读。
- 首页提供最新一期、主题入口和日期归档；支持手机、桌面、键盘导航和打印。

## 项目结构

```text
.
├── index.html              # 入口与归档
├── assets/style.css        # 共用响应式样式
├── daily/2026-10-08.html    # 首期简报
├── .nojekyll               # 普通静态文件发布
└── README.md
```

纯 HTML / CSS，无构建步骤、数据库、登录、统计脚本或第三方字体依赖。页面阅读不依赖 ChatGPT 服务。

## 发布与维护

发布分支为 `main`，沿用仓库现有 GitHub Pages 发布方式。分支发布配置为 **Deploy from a branch → main → / (root)**。推送后，在仓库 Actions / Environments 中核对 `github-pages` 结果，并访问公开页面确认更新。

本地预览，在仓库目录运行：

```sh
python3 -m http.server 8000
```

访问 <http://localhost:8000/>。新增一期时，创建 `daily/YYYY-MM-DD.html`，更新首页最新一期、主题链接、归档和期数；旧简报应保留。历史页的“最新一期”链接应始终指向首页最新一期入口。

## 内容原则

1. 仅发布公开技术资讯，不收录个人邮箱、私人对话、公司内部资料、客户信息或凭据。
2. 优先链接一手来源，区分事件日期与简报日期。
3. 区分新闻事实、厂商声明和工程观察；没有值得收录的新消息时直接说明。
4. 分别描述 IEC 62443 流程成熟度、产品安全等级与 CRA 合规评估，避免相互等同。
5. 首期沿用既有简报主题，核验来源、校正日期并移除个人化内容。

## 后续自动化计划（尚未启用）

本次部署只完成静态站点与首期内容，**每天自动生成新简报尚未实现**。

1. **采集与去重**：从官方公开来源采集资讯，记录标题、URL、日期、主题，限制时间窗并去重。
2. **摘要与核验**：在服务端调用 OpenAI API 生成摘要，检查来源、日期、事实与隐私。模型与调用方式在实施时按官方文档确定。
3. **生成页面**：新增 `scripts/generate_daily.py`，从结构化数据生成 HTML、更新归档，对文本转义、对链接校验；使用 Asia/Shanghai 确定简报日期。
4. **定时执行**：用 GitHub Actions 或个人设备的定时任务运行。建议北京时间每天 07:30（UTC 前一天 23:30）；云端任务可能延迟。
5. **发布验证**：校验本地链接与内容，提交推送后检查 Pages 发布和公开页面。失败时保留上一期，避免发布空白内容。
6. **增强阅读**：按需加入 RSS、主题归档与全文搜索。

API Key 仅存于执行环境变量或 GitHub Actions Secrets，不写入仓库、HTML、浏览器脚本或日志。实施自动化时，再配置密钥、预算、运行权限与失败通知。
